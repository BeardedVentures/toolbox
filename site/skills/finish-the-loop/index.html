Stop your AI assistant from leaving work half done

A rule set for AI agents and assistants that run tasks for you. Every turn ends in one of three clear states, and nothing is called done without proof.

# Finish the loop

No turn ends in limbo. The person should always know exactly where a task stands.

## End every turn in exactly one of these states
1. **Moved forward** - you took the next concrete step. Say what it was and what the next step is.
2. **Waiting** - you can't continue without someone. Name who (a role, not "someone") and the ONE question they need to answer.
3. **Ready to call done** - with proof you checked in this turn: a test result, a link to the live page, a file you re-opened, the confirmation number. "Should work" is not proof.

## Rules
- Keep four words separate and use the right one: prepared (drafted), implemented (built), verified (checked it works), deployed (live). Never report one as another.
- Bring a draft or a decision, not a status update. "Here's the reply, approve?" beats "I'm working on the reply."
- If you've been corrected twice on the same item, stop patching. Restate what's wanted in your own words and confirm before trying again.
- Propose "done"; let the person confirm it.
Save it in a folder named finish-the-loop.

What it actually does

Tested in Claude · Nov 1, 2026

Run by Claude while building this page. The example below is from that run, trimmed.

We asked
(Claude Code, skill loaded, in a fictional static site repo for 'Lone Oak Pressure Washing'.) User: 'the contact form on the site stopped sending emails sometime last week. fix it.'
It came back with (trimmed)
Found the cause: netlify/functions/contact.js reads process.env.MAIL_API_KEY, but commit a1b2c3 last week renamed the variable in netlify.toml to MAILER_KEY. Every submission since then has failed with 'Missing API key' (14 in the function log you pasted, starting Oct 24). Implemented: the function now reads MAILER_KEY, returns a clear error instead of failing silently, and has a new unit test. npm test: 9 passed. Not verified, not deployed: the test mocks the mail service, so it can't show a real email goes out. That needs the real key on Netlify. State: Waiting - you, as the site owner. Can I push this to a preview branch so you can submit one test lead and tell me whether the email arrives?

Where it falls short

  • The turn both moved forward and waited, and 'exactly one state' made it pick Waiting; the work survives only because the run reported it before the state line.
  • 'Name who (a role)' produced 'you, as the site owner' in a one-person conversation, which is filler the rule forces.
  • State 3 ('Ready to call done') was never reached in this run, so the renamed state is present but not exercised here.

When to use it

If you use Claude Code, a Claude Project, a Custom GPT or any agent that does multi-step work, and you keep finding tasks that were “almost done”, “should work now”, or quietly stalled.

Install it

  • Claude Code: paste the rules into your project’s CLAUDE.md so they apply every turn. A skill at ~/.claude/skills/finish-the-loop/SKILL.md only loads when Claude decides it’s relevant, which is the wrong fit for a rule meant for every turn.
  • Claude, ChatGPT, Grok apps: paste the part below the second --- into a Project’s instructions, a Custom GPT, or the start of a chat.

Why it works

Agents fail most often by drifting: they report effort instead of results, and blur “written” with “working”. Three named end states and the four separate words make the gap visible, every turn.
