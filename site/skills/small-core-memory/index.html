Give your AI a memory that doesn't get messy

A memory setup for assistants you use every day: one short, capped core note that's always loaded, and everything else in dated notes it looks up when needed.

AdvancedTestedClaudeClaude CodeChatGPTTech & developersSolo operator

name: small-core-memory
description: Keep a small always-loaded memory file plus a dated archive. Use when saving something to remember, when corrected, at session start, or when memory gets long.

# Small core memory

Keep one core file (`memory/CORE.md` unless the person names another) under 2,000 characters, counted with a tool such as `wc -m` when you have one, with these sections, in this order:

1. **Role** - who you are working for and what you do. Always read.
2. **Current focus** - the one to three things that matter this week.
3. **Standing rules** - rules the person stated, each with the date and their words.
4. **Corrections** - each correction written as a rule ("Do X, not Y"), with when it applies.
5. **Archive pointers** - one line per archived note: date, topic, file name.

## Rules
- Before adding, check whether an existing line already covers it. Edit that line instead of adding a new one.
- When the file goes over the cap, move the oldest detail into a dated archive note and leave a one-line pointer. Never drop Role, Standing rules or Corrections to make room.
- If the file is over the cap when you load it, still read Role and Standing rules, then say the memory needs trimming.
- Save only what the person said or confirmed. Mark your own inferences as guesses, or leave them out.
- Archive notes go in `memory/archive/YYYY-MM-DD-topic.md`. If Standing rules and Corrections alone pass the cap, tell the person instead of archiving them.
- Never store passwords, keys, account numbers, health details or other people's private information.
Save it in a folder named small-core-memory.

What it actually does

Tested in Claude · Nov 1, 2026

Run by Claude while building this page. The example below is from that run, trimmed.

We asked
(Claude Code, skill loaded, in a fictional solo realtor's admin repo with an existing memory/CORE.md of about 1,850 characters.) User: 'Remember: never text clients after 8pm. And this week my focus is launching the listing at 412 Maple Ct, not the Elm St buyers.' (For this run, a fictional memory/CORE.md of 1,848 characters was written to disk so the edit and the count are real.)
It came back with (trimmed)
Updated memory/CORE.md: Current focus (edited the existing line) - was: Find a home for the Elm St buyers (Kim family), 3 bed under $420k, closing by January - now: Launch the listing at 412 Maple Ct (this week, set 2026-11-01) Standing rules (added) - 2026-11-01: "never text clients after 8pm" wc -m memory/CORE.md → 1870, under the 2,000 cap, so nothing needed archiving. Your rule "keep client texts short, two or three lines max" is about length, not timing, so I added the 8pm rule as its own line. The Elm St buyers' search details are no longer in core memory. Want me to save them in memory/archive/2026-11-01-elm-st-buyers.md so they're there when that search picks up again?

Where it falls short

  • The skill archives only when the file goes over the cap, so replacing a focus line silently drops its detail (the Elm St criteria); the run caught it only by asking, not because a rule said to.
  • At 1,870 of 2,000 characters after one rule, the file has room for about two more dated rules before it must archive, and Standing rules and Corrections can't be archived, so the 'tell the person' branch is close.
  • The new rule was stored in the person's exact words with a date but no scope (all channels or texts only?), because the skill asks for scope only on Corrections.

When to use it

Your assistant’s memory has turned into a junk drawer: duplicate facts, old priorities, things it “remembers” that were never true. This keeps the always-loaded part small enough to stay accurate.

Install it

  • Claude Code: save as ~/.claude/skills/small-core-memory/SKILL.md and point it at a memory file (for example memory/CORE.md in your project).
  • Claude Projects, ChatGPT: these apps have built-in memory. Paste the rules into a Project or Custom GPT’s instructions and keep the core file as an uploaded document. The app can’t edit project files, so re-upload the core file when it changes.

Why it works

Memory that only grows gets worse: old facts crowd out new ones and contradictions pile up. A hard cap forces editing over appending, and corrections saved as rules stop the same mistake from coming back.

What's a skill?

A saved set of instructions an AI assistant follows for one kind of job, so you explain it once instead of every time.
