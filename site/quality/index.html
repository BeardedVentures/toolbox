Our quality bar

TOOLBOX quality bar

The rule: this can not be AI slop. The site has to be an impressive show of what AI page-building can do, and every tool on it has to actually help, from someone nervous about AI to a pro hunting for the missing piece.

Fewer excellent items beat many thin ones. When an item fails a check and can’t be fixed, cut it.

npm run quality checks the parts a machine can check, and npm run build runs it first, so a failing item can’t ship. The rest is checked by a person before an item goes in.

Every item

  • Title names the need. Just specific enough that most people recognize their own need in it. Name the job in plain words (“Plan a week of dinners from what you already have”), not the tool or the jargon (“Meal-planning prompt v2”), and not so broad it’s vague (“Cooking help”). The same rule applies to sections and categories.
  • Has a lane (Family & home, Solo operator, Small business, Tech & developers), a level (Beginner, Intermediate, Advanced) and task tags people would actually search for.
  • Specific use case. Says when to use it, in a sentence a reader recognizes from their own week.
  • No made-up facts. No invented stats, testimonials, reviews, customer quotes or “saves X hours” claims. A number on the page has a source link or came from our own run.
  • No filler. None of the banned phrases below, no motivational intros, no “in today’s fast-paced world”.
  • Honest about limits. At least one specific limit or failure mode, written from what we saw, not a generic “AI can make mistakes”.

Prompts and skills

  • Exact inputs. Every blank is in [CAPITALS] and listed in fill:.
  • A real example. example.input and example.output come from an actual run of the prompt as written, trimmed but not polished. Never written by hand.
  • Tested, said plainly. tested: records which model or app it was run in and when. Anything not run says “Not yet tested” on the page. We don’t claim a prompt works in ChatGPT or Gemini until someone runs it there.
  • Better than asking plainly. If the output isn’t clearly better than typing the request in your own words, cut it.
  • Guards against the usual failure. Each prompt tells the AI what not to invent (prices, perks, health claims, sources) and gives it an honest way out (null, [BLANK], “I couldn’t find it”).

MCP tools

  • Says what it can touch in plain words on the card (access:).
  • Setup checked against the maker’s own docs on a stated date (checked:), with a source link.
  • Status is honest. “Tested by us” only after we installed and ran it. Otherwise “Not yet tested by us”.

Guides

  • Sources listed for the facts in it (sources:), from primary sources (the maker, the agency, the original study).
  • Menu paths dated. App menus move; say where to find current steps.

Craft

  • Works at 360px wide with no sideways scroll.
  • Keyboard only: every control reachable with Tab, visible focus, search on / or Ctrl/Cmd-K, Esc closes.
  • Copy buttons on every prompt, skill and config, with a “Copied” confirmation that screen readers hear.
  • Empty states say what to do next (request it), never a blank grid.
  • No tracking, no pop-ups, no account needed.

Banned phrases

npm run quality fails on these in titles, summaries and page text (prompt text is exempt when it tells the AI to avoid them):

unlock, unleash, supercharge, revolutionize, game-changer, game changer, seamless, effortless, harness the power, elevate your, take it to the next level, delve, in today’s fast-paced, cutting-edge, next-level, skyrocket, 10x, magic (as a claim), “AI-powered” as a selling point, testimonial, as seen in.
